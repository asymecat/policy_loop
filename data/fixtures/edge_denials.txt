# --- two events whose markers share one line ---
# Both markers snap to the same line start, so the first opens a zero-length
# block (dropped) and the second opens a block covering the rest of the file.
# The surviving record is therefore one where the FIRST marker's fields win:
# its scontext/tclass/perms are the ones a reader would attribute to it, and
# the second marker's fields are either ignored (key already seen) or contribute
# only what the first did not have. Net effect: one record, first marker's data.
# Reproduce the quirk rather than "fix" it -- the host engine behaves this way
# and the device must agree with it.
avc: denied { read } for scontext=u:r:first_on_line:s0 tcontext=u:object_r:b:s0 tclass=file avc: denied { write } for scontext=u:r:second_on_line:s0 tcontext=u:object_r:b:s0 tclass=file
